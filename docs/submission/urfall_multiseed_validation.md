# UR Fall 多随机种子跨域稳定性验证

## 1. 验证目的

本验证用于回答“同一公开数据实验换一个随机种子后，跌倒预判指标是否大幅波动”。它是公开数据上的工程稳定性证据，不是家庭场景、真实设备或临床有效性结论，也不授权模型自动发布。

## 2. 数据与隔离方法

- 跌倒域：UR Fall 姿态窗口 40 条；
- 日常活动域：UR Fall ADL 姿态窗口 48 条；
- 跌倒样本按序列执行 LOSO；
- ADL 按序列组做确定性留出，留出 ADL 不进入对应折训练；
- 阈值只根据跌倒 LOSO 预测选择，ADL 只在阈值锁定后审计误报；
- 随机种子在运行前固定为 `17`、`42`、`73`，每个种子训练 80 轮。
- 跌倒清单 SHA-256：`54be86baef01d7d8aedae6d3595533bff2bc1c082e3c31c56b473cb10e6e0c36`；
- ADL 清单 SHA-256：`ee0f3c9b023ee28eb7eba9fb066873e795de97c4dcd1f5d0f1b938bfd63d4be1`。

运行命令：

```powershell
python scripts/run_urfall_multiseed.py `
  --fall-manifest <fall-pose-manifest.jsonl> --fall-root <fall-pose-root> `
  --adl-manifest <adl-pose-manifest.jsonl> --adl-root <adl-pose-root> `
  --output-dir outputs/urfall-multiseed `
  --seeds 17 42 73 --epochs 80 --device cuda --recall-floor 0.8
```

## 4. 结论与限制

三次运行的跌倒 F1 波动较小，召回率在既定 `0.8` 下保持一致，说明当前训练链路在这组公开数据上具备初步稳定性。阈值标准差仍然较大，说明部署时不能复用任意单次训练阈值，必须固定发布权重并绑定其校准产物。

同一组种子和数据完成了第二次独立 CUDA 复跑，逐种子 F1、Precision、Recall 与 ADL 误报率一致；阈值出现约 `1e-5` 量级的浮点差异。因此这里声称的是指标稳定性，不声称 GPU 训练逐位确定。

当前 `promoted=false`。主要限制是样本数量较小、来自公开数据、训练窗口与真实萤石摄像头分布仍有差异；因此这些结果只能用于比赛中的可复现性和算法稳定性说明。

机器可读正式汇总为 [`urfall_multiseed_aggregate.json`](urfall_multiseed_aggregate.json)。本地 `outputs/` 仍被 Git 忽略，避免将中间预测和训练缓存误当作正式发布包。
