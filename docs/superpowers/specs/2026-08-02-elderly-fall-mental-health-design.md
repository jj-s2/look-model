# 老年人跌倒与心理健康风险前置预警系统设计

- 日期：2026-08-02
- 状态：方案已确认，等待书面规格复核
- 赛题方向：跌倒风险前置防控、心理健康风险筛查
- 技术路线：路线 A——视觉、睡眠/生理、低频主动筛查的分层决策融合

## 1. 目标

在现有 OpenMMLab 跌倒识别代码上构建一个可演示、可测量、可解释的老年人居家身心风险系统，使用萤石开放平台接入真实设备，形成：

1. 跌倒前风险判断：识别步态不稳、身体晃动、起身困难、扶物行走和近跌倒。
2. 跌倒过程识别：识别站立、坐下、躺下、近跌倒和跌倒，降低正常躺卧造成的误报。
3. 心理健康风险筛查：以低频、主动同意的量表为依据，以睡眠和活动趋势为辅助，只输出风险和建议。
4. 分级预警：将实时事件、长期趋势和数据可靠性共同纳入决策，支持本地提醒、家属通知和事件回溯。

## 2. 明确不做的内容

- 不依据一次表情、一次语音或单晚睡眠诊断抑郁症、焦虑症或其他疾病。
- 不持续录音，不把日常谈话内容作为默认输入。
- 不频繁向老人提问，不自动反复执行完整量表。
- 不宣称取得 SDNL1 的原始毫米波数据；只使用开放平台或设备实际提供且经验证的字段。
- 不自动联系急救机构；比赛原型只通知预先配置的联系人或管理端。
- 不要求老年受试者表演真实跌倒；跌倒动作只能由健康成年人采取安全保护措施模拟，或使用合规公开数据。

## 3. 已有基础与硬件

### 3.1 硬件

- 萤石 C6c：`CS-C6c-V101-1J4WF(4mm)`，负责视频；设备音频和对讲能力通过开放平台能力集及萤石 App 实测确认。
- 萤石无感睡眠伴侣：`CS-EP-SDNL1`，负责平台实际开放的睡眠、心率、呼吸、在床/离床等数据。
- 本地 Windows 计算机和 CUDA GPU，负责模型推理、融合、存储和展示。

### 3.2 现有软件

- `vision/input_adapter.py` 已定义本地视频、摄像头和萤石视频源适配思路。
- RTMDet + RTMPose 已完成人体检测和二维关键点提取。
- MMAction2 PoseC3D 已有 LOSOCV 结果；现有汇总准确率约 0.914，统一阈值结果约 0.934。
- `risk/gait_stability.py` 已有规则型步态风险评分。
- `radar/` 和 `fusion/` 尚未形成实现，可作为明确的新模块边界。
- 迁移到 `F:\邵吉锦\look model` 后仍有旧绝对路径，实施第一阶段统一改为相对路径和环境配置。

## 4. 总体架构

系统采用异步、决策级晚期融合。各模态先独立产生带时间戳、置信度和可用性标记的结果，再由融合层组合；任一非关键模态缺失时，其他模块仍可运行。

```text
C6c 视频 ─> 设备适配器 ─> 人体检测/跟踪 ─> RTMPose ─> PoseC3D/步态特征 ─┐
                                                                        │
SDNL1 ───> 传感器适配器 ─> 睡眠/生理日摘要 ─> 个体基线与趋势 ───────────┼─> 分级决策 ─> 提醒/告警/报告
                                                                        │
主动筛查 ─> 低频问卷或可选语音 ─> 量表分数与完成状态 ──────────────────┘
```

跌倒风险与心理风险分别输出，融合层不生成一个含义不清的“总健康分”。心理和睡眠状态只能作为跌倒风险的背景修正因素，并且必须在结果中显示修正依据。

## 5. 模块设计

### 5.1 配置与密钥

- 仓库路径、权重路径和数据路径统一由项目根目录、命令行参数或环境变量解析。
- `AppKey`、`AppSecret`、访问令牌、设备序列号和验证码保存在本机 `.env`，不得提交到 Git。
- 启动时验证配置，但日志只显示字段是否存在，不打印密钥值。

### 5.2 萤石设备接入

定义两个稳定接口：

- `VideoSource`：输出视频帧、设备时间戳、流状态；音频默认关闭。
- `PhysiologySource`：输出平台实际可得的睡眠/生理记录及字段可用性。

设备接入启动时查询能力集。C6c 无音频或对讲能力时，只禁用语音功能；SDNL1 数据接口不可用时，系统进入“视觉单模态”状态，并在界面和报告中明确标记，不用虚构数据代替真实设备结果。模拟数据只允许在独立的 `demo` 模式使用并明显标识。

### 5.3 视觉感知与跌倒事件识别

沿用 RTMDet、RTMPose 和 PoseC3D：

1. 检测并跟踪主要人体，过滤低置信度和过小目标。
2. 对关键点做置信度过滤、缺失点插值、尺度和平移归一化。
3. 使用滚动骨架窗口推理动作类别。
4. 使用状态机约束状态转换，防止单帧误判：`正常 -> 不稳定/快速下降 -> 地面状态 -> 持续不动`。
5. 正常上床、坐下、弯腰和捡物作为重点负样本。

输出包括动作类别、跌倒概率、状态持续时间、可见关键点比例和事件证据。

### 5.4 跌倒前风险

跌倒前风险不只使用当前规则分数，而是由以下可解释特征构成：

- 躯干左右摆动幅度及变化率；
- 步宽、步频、步态周期不对称；
- 膝、髋角度稳定性；
- 起立用时和重复尝试；
- 扶物、停顿、踉跄和近跌倒次数；
- 最近 7 天相对个人基线的变化。

先保留规则模型作为可解释基线，再训练轻量时序分类器。新模型只有在按受试者划分的验证中优于规则基线时才成为默认模型；否则继续使用规则基线并报告结果。

### 5.5 睡眠、生理与个体基线

SDNL1 数据按实际开放程度接入。可用字段转换为日级特征，例如总睡眠时长、夜间觉醒、离床次数、心率/呼吸统计和缺失比例。系统不把单次心率或呼吸变化解释为心理疾病。

冷启动期为 7 个有效日。冷启动期间只显示实时跌倒事件，不发布个体长期趋势结论。基线采用稳健中位数和四分位范围，逐日缓慢更新，异常日不立即污染基线。

### 5.6 心理健康风险筛查

心理模块包含两个独立来源：

1. **被动状态变化**：睡眠规律、室内活动时长、活动量和昼夜节律相对个人基线的变化，只输出“身心状态变化提示”。
2. **主动量表**：由老人或家属主动发起，或在连续 3 个有效日出现多指标异常后提供一次邀请。完整 GDS-15 的自动邀请间隔不得短于 28 天；老人拒绝后立即结束。

量表文字使用来源明确、许可允许、适合中文老年人的版本，并保留版本和来源。量表分数只用于筛查；中高风险提示“建议由家属或专业人员进一步了解”。涉及自伤相关回答时，不由模型解释，直接产生高优先级人工关注提示。

### 5.7 低打扰语音策略

语音不是持续交互，也不是心理模块的必需条件。

- 默认通过页面或家属端主动启动问卷。
- 连续异常时，系统最多每 7 天询问一次简短关怀问题；21:00 至 08:00 不主动询问。
- 跌倒事件可以立即询问一次“是否需要帮助”，不受上述频率限制。
- 老人回答拒绝、稍后或无响应时立即结束，最多进行一次听错确认。
- 比赛原型优先使用电脑扬声器播放固定录音或 TTS，并在交互期间临时采集音频；C6c 扬声器自动播放只有在 SDK 实测支持程序音频输入后启用。
- 本地 Whisper 可用于短句转写；核心答案采用有限词表匹配。低置信度结果记录为“未确认”，不得猜测。

### 5.8 分级决策与告警

系统维护三个独立结果：

- `fall_event`：实时跌倒事件概率和状态；
- `fall_forecast`：短期跌倒风险趋势；
- `wellbeing_change`：心理/生活状态变化风险及可选量表结果。

默认分级：

- 绿色：正常，仅记录趋势。
- 黄色：单项轻度异常，持续观察。
- 橙色：连续趋势异常、近跌倒或量表筛查提示，通知家属端关注。
- 红色：确认或高度疑似跌倒、跌倒后持续不动、明确求助或高优先级心理安全回答，立即告警。

融合规则必须返回原因列表，例如“连续 3 天睡眠效率下降 + 步态摆动增加”，禁止只显示一个无法解释的分数。

### 5.9 展示与回溯

比赛界面至少包含：设备状态、实时视频骨架叠加、当前风险等级、触发原因、7/30 日趋势、告警记录和数据缺失提示。实时页不展示心理诊断标签。

事件回溯默认只保存关键点、风险记录和告警时间。经用户明确授权后，可保存事件前 10 秒和后 20 秒的视频片段用于复核。

## 6. 核心数据契约

模块间使用统一事件结构，至少包含：

```json
{
  "subject_id": "anonymous-001",
  "timestamp": "ISO-8601",
  "source": "vision|sdnl1|screening",
  "event_type": "fall_event|gait_risk|sleep_summary|screen_result",
  "value": {},
  "confidence": 0.0,
  "quality": {
    "available": true,
    "missing_ratio": 0.0
  }
}
```

融合层按时间窗口读取事件，不直接依赖各模型内部对象，以便单独测试和替换模型。

## 7. 异常与降级处理

- 视频断流：自动重连并记录断流；不得继续声称“实时跌倒监测正常”。
- 人体暂时遮挡：保持短时跟踪，关键点质量不足时不产生高置信度结论。
- SDNL1 离线或字段未开放：保留视觉功能，停用相应趋势修正并显示“生理数据不可用”。
- Whisper/TTS 不可用：问卷退化为页面点击；跌倒告警仍正常工作。
- 网络或令牌失效：指数退避重试，提示重新授权；密钥不写入日志。
- 多模态时间戳偏差：超过允许窗口的数据不融合，并显示数据过期。
- 模型加载失败：服务进入降级状态，不使用随机输出或历史结果冒充实时结果。

## 8. 隐私、伦理与安全

- 采用本地推理优先，只上传萤石平台正常取流所必需的数据和明确配置的告警。
- 默认不保存原始音频；问卷保存结构化答案、分数、版本和时间。
- 默认不保存连续视频；事件片段保存需授权，并设置 7 天默认保留期。
- 身份使用匿名编号；联系人、设备密钥与研究数据分开存储。
- 提供摄像机隐私遮蔽时段、问卷关闭开关和数据删除入口。
- 比赛报告明确说明系统是辅助筛查与预警工具，不替代医生或照护人员。

## 9. 测试与验收

### 9.1 单元与契约测试

- 路径和配置在移动项目目录后仍可解析。
- 三类输入事件的字段、时间戳、缺失值和质量标记可被融合层正确处理。
- 状态机覆盖正常躺下、坐下、弯腰、遮挡、跌倒和跌倒后起身。
- 量表计分、跳过、拒绝、低置信度及频率限制均有测试。
- 告警去重、升级、恢复和设备离线降级均有测试。

### 9.2 离线模型评测

- 继续使用按受试者划分的交叉验证，防止同一人的片段同时出现在训练和测试中。
- 跌倒事件至少报告准确率、精确率、召回率、F1、混淆矩阵和阈值曲线。
- 验收下限：跌倒 F1 不低于 0.90，召回率不低于 0.88；任何新模型不得低于当前已记录基线。
- 跌倒前风险模型与规则基线做消融比较，报告按受试者划分的 F1/AUC 和提前量，不只报告训练集准确率。
- 心理模块不声称临床诊断准确率；验证量表计分正确性、趋势稳定性、解释一致性和缺失数据处理。

### 9.3 真实设备集成测试

- 验证 C6c 取流、延迟、断流恢复、夜间图像和能力集。
- 验证 SDNL1 实际可获得字段、更新周期、离线恢复和时间同步。
- 目标：跌倒事件端到端 P95 告警延迟不超过 2 秒。
- 在有保护措施的情况下由健康成年人完成日常动作和模拟跌倒；正常活动连续测试中目标误报率低于 1 次/小时。
- 验证音频默认关闭、主动交互才启用、拒绝后不重问、每 7 天频率限制和夜间静默。

### 9.4 适老性验收

- 风险提示使用大字号、高对比度、短句和明确颜色文字，不只依赖颜色。
- 紧急确认最多一个问题，回答方式允许语音或单按钮。
- 记录从告警出现到家属确认的时间，并在测试报告中展示。

## 10. 实施顺序

1. 修复迁移后的绝对路径和配置，建立可重复的基线测试。
2. 完成 C6c 真实取流、能力查询和设备健康状态。
3. 把现有姿态、PoseC3D 和步态规则整合为实时状态机。
4. 完成 SDNL1 能力探测、真实字段适配和 7 日个体基线。
5. 完成被动状态变化、主动量表和低打扰交互控制。
6. 完成决策级融合、分级告警、趋势展示和隐私控制。
7. 执行离线、真实设备、适老性和降级测试，形成比赛测试报告和演示脚本。

## 11. 开源项目使用原则

- MMPose、MMAction2：继续作为视觉和动作识别底座，保留 Apache 2.0 声明。
- Whisper：只用于可选的短句转写，保留 MIT 声明。
- openSMILE：仅在确有必要时用于研究演示的声学特征，并在第三方声明中注明其研究/教育用途限制；首版不依赖它。
- OpenFace、DepMamba 等项目不直接复制为核心系统；只参考其多模态特征和时序融合思想，避免许可证、数据集和人群迁移问题。
